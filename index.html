Database Design

Relational Schema & Constraints

Designed and maintained by Poojitha with cascaded foreign keys and domain integrity validation.

Entity-Relationship (ER) Cardinality:
PATIENT (1)
1 : N (One-to-Many)
APPOINTMENT (N)
1 : 1 (One-to-One)
BILL (1)
DOCTOR (1) ──── (1:N) ────▶ APPOINTMENT (N)
patient Primary Entity
  • patient_idINT AUTO_INCREMENT (PK)
  • full_nameVARCHAR(100) NOT NULL
  • ageINT CHECK (age > 0)
  • genderVARCHAR(20) NOT NULL
  • phoneVARCHAR(20) NOT NULL
  • addressVARCHAR(255)
doctor Primary Entity
  • doctor_idINT AUTO_INCREMENT (PK)
  • full_nameVARCHAR(100) NOT NULL
  • specializationVARCHAR(100) NOT NULL
  • phoneVARCHAR(20) NOT NULL
  • consultation_feeDECIMAL(10,2) CHECK >= 0
appointment Relational Junction
  • appointment_idINT AUTO_INCREMENT (PK)
  • patient_idINT FK → patient
  • doctor_idINT FK → doctor
  • appointment_dateDATE NOT NULL
  • appointment_timeTIME NOT NULL
  • statusScheduled | Completed
bill Billing Entity
  • bill_idINT AUTO_INCREMENT (PK)
  • appointment_idINT FK → appointment
  • amountDECIMAL(10,2) CHECK >= 0
  • payment_statusPaid | Pending
  • bill_dateDATE NOT NULL
Object-Oriented Programming

Classes & Objects
